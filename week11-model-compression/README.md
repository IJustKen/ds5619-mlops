In this lab, we completed a model compression benchmark that evaluates magnitude based pruning and INT8 quantization against a baseline linear classifier model. The dataset consists of 256 model weights, where only 40 are informative signals and 216 are near zero noise, evaluated across 300 test examples. The goal was to measure model size in bytes, inference accuracy, and latency, and see the trade off them.

FUNCTIONS IMPLEMENTED AND THEIR EXPLANATIONS

NOTE: The code has been commented to explain the working of each function

model_size_bytes
This function computes the total byte footprint of the model using dense storage. It multiplies the number of elements in the weight vector by the bytes required per data type, such as 4 bytes for 32 bit floating point numbers or 1 byte for signed 8 bit integers.

prune_weights
This function implements magnitude based unstructured pruning. It calculates how many weights to remove based on the sparsity fraction, identifies the indices with the smallest absolute values, and sets those specific indices to 0.0 while preserving the remaining weights, in a new list.

sparse_coo_size_bytes
This function calculates the memory required if only non zero weights are stored using a Coordinate (COO) format. Every surviving non zero value pays a storage cost for both its actual numerical value and its positional index.

quantize_int8
This function implements symmetric linear quantization. It finds the maximum absolute float value in the weight array, computes a scale factor by dividing that maximum by 127, and scales each weight to a signed 8 bit integer clamped between -127 and 127.

benchmark_model
This function evaluates a set of weights by running prediction passes over the test dataset. It calculates prediction accuracy as the fraction of correct predictions over total examples, and measures average pass time in milliseconds. In the end it outputs a report for the model specifying accuracy, model size bytes, latency per pass in ms. This report is part of the compression report that is generated byb running the pipeline.
